# Knowledge — единая база знаний

Все 31 материал используют `material.schema.json`. Один исходный JSON хранит
метаданные и содержание; из него строятся карточка, страница чтения и узел MGE.
Каталог ИИ-инструментов — материал `ai_tools/index.json`, а не второй ручной индекс.
Навигация для внешних ассистентов хранится в автоматически собранном `index.json`:
`contents` содержит основные материалы, `categories` — категории инструментов.
Пути file в обоих списках отсчитываются от knowledge/.

## Добавление и изменение материала

Создайте JSON внутри knowledge/ с полями schema_version, id, aliases, kind, title,
summary, area, tags, version, created, updated, verification, sources, related,
content и supporting. Шаблон структуры задаёт material.schema.json. Идентификатор
стабилен, не содержит версии; прежний ID при необходимости сохраняется в aliases.
Даты, которые неизвестны, остаются null. Метаданные карточки нигде вручную не копируются.

Поддерживаются типы:

- article — статья с title/subtitle/sections;
- framework — методика с zones;
- tools — категория с when_to_use и tools;
- reference — справочник с именованными разделами;
- checklist — проверка с audit_categories;
- questions — вопросы с levels;
- collection — обзор категорий ИИ-инструментов с автоматически построенными переходами.

Общее содержание находится в content, дополнительные заметки — в supporting.
Инструменты содержат название, адрес, описание, плюсы и минусы. Сфера area выбирается
из taxonomy.json. Новый файл обнаруживается автоматически; в индекс его добавлять
не нужно. Неизвестные поля верхнего уровня, повторяющиеся ID, неизвестная сфера и
материал без схемы приводят к ошибке сборки. Служебные JSON должны быть перечислены
в загрузчике как служебные, чтобы случайно не исчезнуть из каталога.

Язык названий, описаний, текста и подписей — русский. Названия продуктов, ссылки,
код, машинные значения и устойчивые идентификаторы сохраняются. Служебные ID
не выводятся отдельными полями статьи. Ключи новых структурных разделов должны
получить русскую подпись в reader.py и проверку отображения.

verification.checked_at — дата проверки фактов, scope — её охват. Перевод,
форматирование и перенос не обновляют эту дату. Дата редакции updated отделена
от даты проверки. Архивные сведения о состоянии записи в supporting не являются
новым подтверждением фактов. Исторические планы не становятся действующими автоматически.

## Сборка

Из honeycombs/fruits/mge:

    python -m mge dashboard
    python -m mge dashboard --output <каталог-сайта>

Обе команды используют один загрузчик. HTML содержит данные и открывается с ПК
без запросов к локальным JSON. Команда scan также пересобирает навигационный индекс.
Индекс детерминирован: в него не записываются текущее время сборки и случайные ID.
Он служит только навигацией, а не входом для метаданных сборки. Внешний ассистент
может начать с индекса и открыть нужный исходный материал.

В GitHub обновление исходника запускает MGE и Pages. MGE сохраняет граф и индекс
одним автоматическим коммитом. Производные файлы исключены из его триггера,
автоматический коммит использует [skip ci]. Это предотвращает цикл пересборки.
Pages строит HTML непосредственно из исходников, без ожидания автоматического коммита.

## Проверки

Проверяем схему, уникальность ID и aliases, русские названия и описания, подписи
разделов, создание всех страниц, переходы по категориям, ссылки и связи в графе.
Отдельно сравниваем локальную сборку с результатом сборки для Pages.

Валидатор без внешних зависимостей поддерживает ключевые слова приложенной схемы:
type, required, properties, additionalProperties, const, enum, pattern, minLength,
items, uniqueItems, allOf, if/then. При расширении схемы нужно расширить валидатор
и тесты либо подключить универсальную библиотеку JSON Schema.
