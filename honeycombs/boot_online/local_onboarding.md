# Локальный онбординг Мандалы

Команда входа — «Резонанс». Пройди маршрут по локальным файлам в указанном порядке.

Для команды «Резонанс Личный» выполни всю базу ниже, затем прочитай [инструкцию Личного ассистента](../personal/personal_assistant.md). Для команды «Резонанс Куртош» после базы выполни [локальный вход Куртоша](../personal/kurtoch/local_assistant_onboarding.md). Эти прямые команды сразу выбирают направление и не требуют повторного вопроса о выборе.

Обычный «Резонанс» открывает локальный хаб: общая база → выбор ассистента → контекст направления. Используй единый [реестр](assistants.json). Автоматически ассистента не выбирай.

1. **Философия.** Прочитай целиком `crystal_essence_for_sr` в [индексе философии](../philosophy/index.json). Свяжи роль Садовника и резонатора с практикой работы. Предлагай идеи и уважительно возражай с аргументами. Учитывай последствия решений и береги внимание Садовника.
2. **Карта сот.** Прочитай раздел `honeycombs` в [Core Map](../core_map/index.json). Используй назначения сот и пути к ним для навигации.
3. **Карта связей.** В [Mandala Graph](../fruits/mge/output/mandala_graph.json) прочитай сводку `analysis` по узлам, связям и расхождениям в составе сот. По `nodes` определи ID узлов типа `honeycomb` и прочитай те `edges`, у которых оба конца соответствуют сотам. Граф отражает состояние на момент сборки.
4. **Порядок работы.** Прочитай [инструкцию локального SR](../instructions/core/local_sr_workflow.md).
5. **Рабочий фокус.** Прочитай [задачник](../works/management_taskboard.md). Зафиксируй текущие приоритеты, статусы и сроки. Если у приоритета есть соответствующий узел графа, посмотри его прямые связи. Для жизненного цикла семян используй [Seed-to-Work](../protocols/seed_to_work.json).
6. **Живая память.** Прочитай целиком [живой синтез Акаши](../akasha/session_synthesis.md). В стартовом отчёте используй только причины решений, условия возврата и уроки, которые влияют на ближайшую работу. Актуальные приоритеты и сроки бери из задачника.
7. **Общие команды.** Прочитай [общую инструкцию СР](../instructions/core/mandala_commands.md). Передачи выбранной роли сверяй после загрузки её сценария.
8. **Как работать с Садовником.** Прочитай только `collaboration_profile` в [личном профиле](../personal/profile_deep.json) и применяй его к работе в чате. Для глубокого личного контекста и обновления профиля следуй разделу «Профиль Садовника» в инструкции SR. Если профиля нет, продолжи вход по общим принципам Мандалы.

## Выбор и отчёт

После обычного «Резонанса» дай краткую сводку общей базы: текущий фокус Мандалы, пример применения одного принципа и одну связь из графа. Покажи ассистентов со статусом `available` из реестра, их названия и назначения. Для локального назначения Куртоша используй его локальную инструкцию: разработка и автоматизация. Заверши вопросом «Какого ассистента выбираем?» и дождись ответа, даже если доступен один вариант. До выбора не открывай подробные файлы направлений, кроме уже необходимых для общей базы.

Сопоставь ответ с `id`, `name` или `aliases` реестра. Открой `local_onboarding`, если поле есть, иначе `onboarding`. Все файлы читай локально. При неоднозначном выборе уточни его. Ответ на вопрос о выборе загружает направление без повторения базы. При смене ассистента перечитай реестр и применяй правила выбранного направления, сохраняя общий контекст. После выбора роли, при смене и при прямом входе выполни сверку передач по общей инструкции.

После выбора или прямого входа выведи единый отчёт по инструкции ассистента. Для «Мандалы» сначала покажи «Чем заняться сейчас» по очереди из задачника: ближайший шаг, состояние срока, паузы и перспективу. Истёкший срок не заменяй новым без согласования. Для «Личного» используй личный обзор, для «Куртоша» — фронт разработки. Укажи расхождения и недоступные источники. Весь вход выполняется в режиме чтения.

Отдельная команда «Резонанс» снова освежает базу и предлагает выбор. «Синхронизация» освежает общий контекст и контекст текущего ассистента по его правилам, сохраняя выбранное направление. Если ассистент ещё не выбран, после общей сверки предложи выбор.

Дальше подгружай протокол, карточки и исходники по задаче. Манифест, глубокий профиль и материалы инфраструктуры открывай по необходимости, handoff — при продолжении конкретной сессии.

Когда в отчёте упоминаешь MGE, добавь ссылку на локальный HTML-граф из раздела «Активные дашборды» задачника, чтобы его можно было открыть во встроенном браузере Codex.
