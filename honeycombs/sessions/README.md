# Sessions — передача работы между чатами

[Общий файл передач](chat_handoffs.json) хранит один актуальный блок на рабочий чат.
При команде «Новый чат» или первом значимом сохранении выбери свободный устойчивый
ID, например `mandala-local-mge`, и назови его в отчёте. Используй этот ID дальше.
Переименование чата меняет `title`, а ID сохраняется. Для нового диалога используй
свой ID, если Садовник явно не продолжает прежний. Сверяй принадлежность записи
по известному ID или явному подтверждению Садовника.
Статус описывает вклад чата, а состояние работы определяется её задачником.

Блок содержит `role` (ID из реестра), `mode` (local или external), `focus`,
`updated` (дата или время ISO), `status` (active, paused, cancelled), `result`
(что изменилось и почему), `next_step` (следующий шаг или условие возврата),
`sources` (пути от корня или проверенный коммит) и `affects` (ID затронутых
ролей). При регистрации добавь `title` с точным названием текущего чата.
В прежних блоках поле может отсутствовать до подтверждения названия. При наличии
укажи `work_id`. Пиши кратко. Незавершённые решения обозначай явно.

При записи замени только свой блок, сохрани остальные. Локально получи контрольную
сумму командой `python honeycombs/sessions/update_handoff.py` перед чтением файла.
Передай новый блок JSON через stdin в тот же скрипт с аргументами
`--chat <id> --expect <сумма>`. При несовпадении версии перечитай файл и проверь,
не изменилась ли также твоя запись. Если изменилась, сначала сверь смысл правок.
Команда чтения передач и обычный онбординг записей не создают.

Перед каждой публикацией передачи перечитай `chat_handoffs.json` из свежей
`main` на GitHub, даже если уже выполнял «Синхрон». Локально получи свежую
ревизию через `git fetch origin main` и используй её как основу публикации,
сохранив рабочую копию и её локальные правки. Перенеси в свежий файл только
согласованные изменения своего блока. Если он тоже изменился на GitHub,
сначала сверь оба варианта и сохрани независимые изменения.

При записи через подключение GitHub используй проверку версии файла (SHA)
или ожидаемой ревизии ветки. При публикации через Git подготовь изменение
поверх проверенной `main` и используй обычный push без принуждения. Если
публикация отклонена из-за новой версии, снова прочитай свежий файл, собери
изменение поверх него и повтори проверку. Если безопасная запись недоступна,
сохрани подготовленный блок локально или в ответе и укажи, что он ещё не
опубликован. После записи проверь свой блок в `main`.

Подробные передачи в `sync/` открывай по ссылке из блока или карточки работы.
Личные передачи остаются в `personal/.session-sync/`. В общий файл выноси только
согласованный итог, затрагивающий другие чаты, без приватных подробностей и
переписки. История общего блока остаётся в Git. Прежние схемы по именам моделей
служат историей. Чтение и полномочия для команд задаёт
[общая инструкция СР](../instructions/core/mandala_commands.md).
