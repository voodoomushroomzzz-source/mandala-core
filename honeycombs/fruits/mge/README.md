# MGE — граф и дашборды Мандалы

Модуль строит граф связей, главную страницу и каталоги Works, Knowledge, Fruits
и личных задач. Исходные данные принадлежат соответствующим модулям.
Работа: W-T-20261015-MGE; продукт: fruit-mge-001.

## Источники и результаты

| Что меняем | Источник |
|---|---|
| Сканирование и связи | mge/core/parser.py, scanner.py, graph.py |
| Каталоги и карточки | mge/dashboard.py |
| Загрузка Knowledge | mge/knowledge.py |
| Страницы чтения | mge/reader.py |
| Главная и значки | index.html, assets/ и manifest.webmanifest в корне репозитория |
| Автоматическая сборка | .github/workflows/build-mge-graph.yml и pages-deploy.yml в корне |

output/ и honeycombs/knowledge/index.json — результаты сборки. Остальные исходники
смотри по [Knowledge](../../knowledge/README.md), [Works](../../works/README.md),
[Personal](../../personal/README.md) и родительскому [Fruits](../README.md).
Правила личных карточек находятся в personal_taskboard.md модуля Personal.

Меняй данные в их модуле, представление — в коде MGE. Новому структурному полю
Knowledge нужна русская подпись в reader.py. Сохраняй устойчивые ID, якоря карточек
и опубликованные адреса страниц. При изменении автоматизации сверяй триггеры,
состав производных файлов и отсутствие цикла сборки; актуальная логика — в workflow.

## Сборка и проверка

Из honeycombs/fruits/mge, с Python 3.12 или новее:

    python -m mge scan
    python -m mge dashboard
    python -m mge dashboard --output <каталог-сайта>
    python -m mge commands --output <пустой-каталог-справочника>
    python -m unittest discover -s tests

scan собирает граф и навигационный индекс Knowledge. dashboard дополнительно
строит каталоги и страницы чтения. Для изменения кода выполни относящиеся к нему
тесты и сборку. При изменении представления проверь получившуюся страницу;
при изменении общей сборки сравни локальный результат с отдельным каталогом сайта.
Проверь ссылки, уникальность ID и диагностику графа, не скрывая обнаруженные ошибки.

Для узлов Works граф берёт название, статус и краткое описание из исходной
карточки. Используется `short_description`, если оно заполнено, иначе
`description`, с сокращением до 420 символов. Для обновления меняй карточку:
локальная сборка и существующие GitHub Actions подхватят поля автоматически.
Статус узла отражает карточку на момент сборки. Текущую очередь и согласованные
сроки сверяй с [задачником](../../works/management_taskboard.md).

Для открытия на ПК используй index.html в корне. Каталоги и страницы чтения
встраивают данные и не требуют доступа браузера к JSON. Нейронная карта
работает на Canvas без CDN и сетевых библиотек. Поведение значка ярлыка зависит от браузера.
Сборка для GitHub Pages использует те же исходники и команду dashboard.

На главной под личными задачами расположен справочник «Команды Мандалы».
Его описания берутся из таблицы в общей инструкции СР. Для самостоятельной
публичной страницы команда `commands` создаёт только `index.html` в указанном
каталоге. Передавай ей отдельный пустой каталог для публикации справочника.
Полная сборка dashboard включает личные данные и подходит для локального
просмотра или размещения с ограниченным доступом.

## Личные данные и автоматическое обновление

Главная `index.html` содержит вход в `output/personal.html`. Страница строится из
`personal/current_movement.json` (фокус, состояния, цели, следующие шаги и контекст)
и `personal/personal_tasks.json` (согласованный фронт). Отдельный блок
«Повседневное» читает `personal/everyday_tasks.json`: покупки и мелкие дела
с собственными статусами; завершённые сворачиваются и не попадают в доску
приоритетов. Ссылочные задачи разрешаются
при сборке из исходников, например `career.json`; их сроки не копируются вручную.

После изменения личных данных workflow Build MGE Graph запускает **dashboard**,
а не только scan: обновляет и сохраняет HTML-каталоги вместе с графом. Deploy Pages
также строит полный сайт из актуальной main. При включённой публикации Pages из
ветки встроенный `pages build and deployment` может выложить снимок из репозитория;
после его успешного завершения Deploy Pages повторно публикует сгенерированный
сайт. Его собственное завершение не запускает повтор, цикла нет.

### Работа с данными без правки сайта

| Данные на личной странице | Единственный источник |
|---|---|
| Покупки и небольшие бытовые дела | `honeycombs/personal/everyday_tasks.json` |
| Согласованные личные задачи | `honeycombs/personal/personal_tasks.json` |
| Фокус и направления | `honeycombs/personal/current_movement.json` |
| Поля ссылочной задачи | Запись в исходном JSON, указанном в `source_file` и `record_id` |

Добавление губок, смена названия пункта, статуса или срока — изменение только
соответствующего JSON в сотах. HTML в `output/` и код генератора для этого
вручную не редактируются. Не создавай параллельную копию списка в HTML или Markdown.

Цепочка: сохранение исходного JSON в `main` → автоматический запуск GitHub Actions
→ чтение JSON генератором → сборка HTML → публикация Pages. Браузер получает
готовую страницу, а не запрашивает JSON при каждом открытии. Поэтому публикация
имеет задержку; уже открытую вкладку нужно обновить. Такой способ сохраняет
возможность читать сгенерированные каталоги локально без сервера.
Локальный сайт требует синхронизации копии и команды `python -m mge dashboard`.

Новый пункт в поддерживаемой форме не требует разработки. Произвольный новый
JSON-файл или неизвестное поле не становятся новым блоком автоматически:
для нового представления отдельно подключают источник в генераторе.

Успех scan не подтверждает обновление personal.html. При проверке изменения
представления или ошибки синхронизации проверь сборку/публикацию и фактическую
страницу. Обычная запись данных во внешнем чате следует
[общему правилу сохранения](../../instructions/core/external_context_saving.md#проверка-страниц-и-сборок):
без обязательного открытия страницы и ожидания Actions после каждого пункта.
Успешная запись JSON и подтверждённое обновление сайта — разные результаты.

## Нейронная карта

Исходники представления: `mge/reporters/neural_map.html` и `neural_map.js`;
`html_reporter.py` встраивает их и данные в один HTML. Соты — крупные ядра,
работы, знания и продукты группируются возле своей соты. Реальные межгрупповые
связи собираются в пучки: толщина и яркость ограниченно растут с их числом.
Одинаковые записи from/to/type не увеличивают вес; разные типы и направления
сохраняются. Размер малого узла зависит от числа уникальных соседей, а не приоритета.

Доступны поиск, фильтры, выбор узла/пучка, переход к исходнику, перемещение,
масштаб колесом, кнопками и жестом двух пальцев. При выборе пучка показаны
его реальные связи; фильтры пересчитывают пучки по видимым данным. Без
декоративных узлов и связей. Анимация работает во время взаимодействия и затухания,
после успокоения карта не перерисовывается постоянно. Тест модели:
`python -m unittest discover -s tests` (для JS-проверки нужен Node.js).

Палитра карты: `core_map` — зелёный, остальные соты — фиолетовый,
малые узлы — индиго. Предупреждения о расхождениях сохраняют сигнальный цвет.
Перетаскивание фиксирует только захваченный узел, а пружины вдоль реальных
связей подтягивают соседей с задержкой. Слабые якоря удерживают форму,
демпфирование гасит колебания. Кадровый шаг ограничен, скрытые узлы
не участвуют в движении; после затухания цикл засыпает.
Учитывается prefers-reduced-motion: хвост движения короче.
Фон перемещает камеру, два пальца масштабируют. Раскладка меняется только
в текущем просмотре, исходные данные не переписываются. Это 2D-модель упругой
сети, без 3D-движка.

Узлы имеют процедурную волокнистую фактуру: мягкий неровный контур и
переплетённые нити без белого глянцевого блика. Рисунок детерминирован по ID,
рисуется в кешированный Canvas-спрайт один раз и не пересчитывается на каждом
кадре физики. У малых узлов меньше нитей; подробная фактура раскрывается при
приближении. Изображения и внешние ресурсы для фактуры не загружаются.
